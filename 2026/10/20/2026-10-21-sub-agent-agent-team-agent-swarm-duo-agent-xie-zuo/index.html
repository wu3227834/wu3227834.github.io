Sub-agent、Agent Team、Agent Swarm：为什么一个 AI 不够用了

一个 Agent 已经可以思考、查资料、调用工具、保存记忆并持续执行任务，但复杂任务仍然可能让它忙不过来。

例如让一个 Agent 分析一年内的 AI Agent 行业、研究 50 家公司、比较产品、融资、团队和技术路线，再写一份报告。它需要不断搜索、整理、写作和校验，Context 会越来越大，执行也会越来越慢。

既然任务可以拆开，为什么不让多个 Agent 分工？这就出现了三个概念：

  • Sub-agent：主 Agent 临时找来的专家；
  • Agent Team：多个职责明确、长期协作的 Agent；
  • Agent Swarm：根据任务动态创建和组织 Agent。

Sub-agent：临时专家

假设一个 Research Agent 要分析全球 AI 语音输入产品。它可以把工作拆成中国市场、日本市场、美国市场和技术路线，再为每个方向创建一个 Sub-agent。

Sub-agent 可以并行工作，也可以拥有独立的 Prompt、Tools 和 Context。这样每个 Agent 只处理自己的范围，信息更聚焦，主 Agent 最后负责汇总。

Sub-agent 的两种常见协作方式是：

  • Agents as Tools：主 Agent 保持控制，把其他 Agent 当成专业工具调用；
  • Handoff：主 Agent 把任务直接交给另一个 Agent 继续处理。

Sub-agent 的重点不是“同时运行很多 AI”，而是把复杂任务交给更专门的 Agent。

Agent Team：固定的 AI 组织

Agent Team 比 Sub-agent 更像长期存在的团队。每个 Agent 有明确角色、Prompt、Tools、Skills 和任务边界。

一个软件开发 Team 可以是：

Research Agent 负责检索和来源验证，Coding Agent 负责代码仓库和 Terminal，Data Agent 负责 SQL 和 Python，Reviewer Agent 不负责生产，只负责检查。

多 Agent 的另一个价值是交叉验证：

这相当于把现实团队中的分工、Review 和反驳机制搬到了 Agent 世界。

Agent Swarm：动态形成组织

Agent Team 的组织结构通常提前写好，而 Agent Swarm 的数量和关系是在解决问题的过程中动态形成的。

例如调查一家公司的供应链风险时，Agent 可能先研究供应商，发现一家供应商来自欧洲后临时创建法规 Agent；发现涉及芯片后再创建半导体 Agent；出现财务异常后再创建财务分析 Agent。

因此可以这样理解：

  • Agent Team 更像组织架构稳定的公司；
  • Agent Swarm 更像按需聚集和消散的蜂群。

Agent Swarm 目前没有一个像 MCP 那样统一、严格的技术定义。它可能是 Manager 加 Worker，也可能允许 Agent 互相创建，还可能采用去中心化协作。更稳妥的理解是：它代表从固定编排走向动态协作的方向。

多 Agent 不是越多越好

多 Agent 适合：

  • 可以大量并行的任务；
  • 需要跨越大量信息的研究；
  • 需要多种不同工具的工作；
  • 需要独立视角交叉验证的任务。

多 Agent 不一定适合强依赖同一份 Context 的任务。例如修改同一个函数时，同时派出十个 Coding Agent，可能只会产生文件冲突和协调成本。

一个 Agent 能稳定完成的任务，就没有必要强行拆成十个。多 Agent 的目标不是增加数量，而是让不同 Agent 在适合自己的边界内工作。

为什么一个 AI 不够用了

一个 Agent 会受到几个天然限制：

  1. Context 有限：同时处理太多方向会互相干扰；
  2. 时间有限：一个 Agent 逐项执行，本质上仍然偏串行；
  3. 专业能力不同：搜索、写代码、数据分析和 Review 需要不同工具与方法；
  4. 自己难以检查自己：独立 Agent 可以提供不同视角。

Multi-agent 解决的是任务组织问题：把一个超级复杂的问题，拆成多个清晰、可并行、可验证的小问题。

如何选择协作方式

场景更适合的方式
临时拆一个研究方向Sub-agent
长期固定的软件研发流程Agent Team
任务边界一开始不清楚Agent Swarm
单个 Agent 已能完成保持单 Agent

未来更重要的能力，可能不是“拥有一个无所不能的 Agent”，而是让一个 Agent 知道：什么时候自己完成，什么时候找专家，什么时候组建团队。

Agent 正在从“一个 AI 干活”走向“多个 AI 组织协作”。

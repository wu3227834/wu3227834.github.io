大语言模型擅长理解和生成文字，但它本身不会读取文件、运行程序、查询数据库或操作网页。要让它真正做事，需要把能力接到模型周围。

可以先记住三句话：

  • Tool 是我能做什么。
  • MCP 是我怎么接入这些能力。
  • Skill 是这件事应该怎么做。

Tools：具体的行动能力

现实任务往往不只是生成文字。例如“分析上个月的销售情况并发送总结邮件”，至少需要读取数据、计算指标、生成图表、找到收件人、创建邮件并发送。

常见 Tool 包括：

  • Search：搜索互联网或知识库；
  • Shell：执行命令和程序；
  • File：读写文件；
  • Browser / Computer Use：操作网页和软件；
  • Python / Calculator：执行计算；
  • Database：查询和更新数据；
  • Email：读取或发送邮件。

Tool 让模型拥有影响外部世界的能力，可以把它理解成 Agent 的手和脚。

MCP：统一连接工具和数据

当 Agent 需要连接 GitHub、Slack、Notion、数据库和公司内部系统时，如果每个 AI 应用都单独开发一套接口，维护成本会很高。

MCP，全称 Model Context Protocol，可以类比成 USB。不同设备内部实现不同，但都通过统一接口连接到电脑。MCP 也提供了相对统一的方式，让 AI 应用发现和调用外部能力。

Skills：可复用的工作方法

拥有工具不等于会做复杂任务。

如果让 Agent “做一份竞品研究报告”，它还需要知道先搜什么、查多少来源、如何判断可信度、什么时候停止搜索、报告采用什么结构，以及哪些结论必须附来源。

这些问题不是 Tool 的职责，而是 Skill 的职责。Skill 更像一份可复用的 SOP 或工作手册，把某一类任务需要的步骤、资源、约束和验收标准封装起来。

总结

如果把 Agent 比作一个员工：LLM 是大脑，Tools 是手和脚，MCP 是连接外部系统的通用接口，Skills 是工作手册。

Agent 的能力并不来自某个单独技术，而来自这些部件的组合。Prompt 和 Context 让它知道目标与背景，Tools 和 MCP 让它可以行动，Skills 让行动变成可重复的方法。
